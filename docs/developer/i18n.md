# Languages

The website's text is in [Paraglide](https://inlang.com/m/gerre34r/library-inlang-paraglideJs) messages: never write
text a visitor reads into a component. The API is not translated: its error messages are for developers, in English.

:::{warning}
**The Spanish translation is a machine translation.** It was produced by an AI model, for testing the website's
localisation, and has not been reviewed by a Spanish speaker. Every page shown in Spanish says so. Do not treat it as
an authoritative translation; the English text is the reference.
:::

## Translations

| Locale  | File               | Status                                  |
| ------- | ------------------ | --------------------------------------- |
| English | `messages/en.json` | Base locale                             |
| Spanish | `messages/es.json` | Machine translated (AI), not reviewed   |

The files are in `packages/catalogue/messages/`; the locales are listed in `project.inlang/settings.json`.

## Machine translations

A locale whose messages were translated by machine, and not yet reviewed by a speaker of the language, is listed in
`MACHINE_TRANSLATED` (`src/lib/i18n.ts`). Every page in such a locale shows the `machine_translation_notice` message,
in that language, at the top of the page: it says that the page was translated by machine, that the translation has
not been reviewed, and that the English version is the reference.

To have a machine translation reviewed:

1. A speaker of the language reads every message in its file against `en.json`, and corrects it.
2. In the same pull request, the locale is removed from `MACHINE_TRANSLATED`, and its status above becomes
   "Reviewed by …". The notice then no longer shows.

A new locale translated by machine is added to `MACHINE_TRANSLATED` in the change that adds it.

## Adding or changing a message

1. Add or change it in `en.json`, with a `snake_case` key.
2. Add or change it in every other locale's file in the same change. A changed message in a reviewed locale makes that
   locale's translation unreviewed until a speaker checks it.
3. Use it as `m.<key>()` from `#lib/paraglide/messages.js`; a message with placeholders takes them, as
   `m.error_heading({ status })`.

The messages test (`tests/unit/messages.test.ts`) fails if a locale is missing a message, has one English does not,
leaves one empty, or changes a message's `{placeholders}`. Components' tests check what they render against the
message files, not copies of the text.

## How a locale is chosen

`project.inlang/paraglide.config.ts` sets the order: the cookie the language picker sets, then the browser's preferred
language, then English. URLs are not localised (no `/es/…`), so the API's paths never change, and the API and the
health check are excluded from the middleware altogether (`handleI18n`, `lib/server/http/i18n.ts`). The page's
`<html lang dir>` is set for its locale.

Paraglide compiles the messages into `src/lib/paraglide/`, which is generated and not committed: the Vite plugin does
it for `dev`, `build` and the tests, and `pnpm i18n:compile` (run by `prepare`, `typecheck` and `check`) for the tools
that do not run Vite.

## Adding a locale

1. Add its code to `locales` in `project.inlang/settings.json`.
2. Create `messages/<code>.json` with every message translated.
3. If it was translated by machine, add it to `MACHINE_TRANSLATED`, and to the table above as such.
